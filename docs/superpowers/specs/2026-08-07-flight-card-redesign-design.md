# 航班卡片布局重构设计

## 目标

在不增加折叠态时间轴行高的前提下，把左侧航班卡重构为明确的进港、出港双段信息。固定卡宽维持 260px，折叠态行高维持 140px；长航班号、标记较多、进出港类型不同等极限数据也必须稳定显示。

## 信息层级

卡片固定为四层，中间使用一条弱分隔线区分进港与出港：

1. 进港主行：进港航班号、STA、进港状态、进港机位、进港航班类型。
2. 进港标记行：进港标记、标记溢出入口、添加按钮。
3. 出港主行：出港航班号、STD、出港状态、出港机位、出港航班类型。
4. 出港标记行：出港标记、标记溢出入口、添加按钮；视频播放按钮固定靠右。

航班号与时间延续当前配色：进港绿色、出港蓝色。状态和机位使用同色系纯文字，不再使用融合胶囊。航班类型沿用现有语义色文字，不使用状态胶囊。

## 航班类型规则

- `arrFlightType` 与 `depFlightType` 相同时，只在进港主行最右显示一次。
- 两者不同时，分别显示在对应主行最右。
- 缺失单侧类型时，只显示存在的一侧。
- 迁移期间允许回退到旧 `flightType`，避免既有数据空白。

## 航班标记与添加

- 数据模型新增独立的 `arrTags` 与 `depTags`。
- 进港、出港标记行各有独立 `+` 按钮，分别写入对应字段。
- 两个入口复用同一套标记选项、颜色映射和“已添加不可重复选择”规则。
- 选择器使用 Portal 显示在当前最高层级，避免被卡片、时间轴或相邻航班裁切。
- 标记过多时，按可用宽度保留部分标记并显示 `…`；`+` 始终可见且位于可见标记末尾。
- 出港标记行还要为右侧视频按钮预留固定空间，因此出港可见标记数可少于进港。
- 详情面板仍可展示兼容的合并标记集合；本次不重构详情面板的信息结构。

## 极限数据规则

- 7 字符及以下航班号使用常规字号。
- 8–10 字符航班号使用紧凑字号与字距，完整展示，不使用省略号。
- 测试数据新增 `ZZMZT6343 / ZZMZT6344`，同时覆盖长机位、类型相同、类型不同及标记溢出。
- 时间、状态、机位与类型列保持固定节奏，长航班号不能挤压相邻字段或造成换行。

## 数据模型与兼容

`Flight` 新增以下可选字段：

```ts
arrTags?: string[];
depTags?: string[];
arrFlightType?: FlightType;
depFlightType?: FlightType;
```

现有 `flightNo` 的首段作为进港航班号，`codeshare` 作为出港航班号。测试数据中不再把两个航班号同时写进 `flightNo`。旧 `tags` 与 `flightType` 暂时保留，作为详情面板及迁移数据的兼容来源。

## 组件边界

- 从 `GanttRow` 中提取航班卡内部展示组件，避免继续扩大时间轴组件职责。
- 提取纯函数处理航班号字号、类型去重、标记回退、可见标记与溢出数量。
- 卡片通过已有航班更新链路写回进港或出港标记，不在组件内维护脱离数据源的副本。
- 视频按钮继续阻止事件冒泡，点击卡片其他区域仍打开航班详情。

## 交互与异常处理

- 点击 `+` 只打开对应航段的标记选择器，不打开航班详情。
- 点击选择器外部关闭选择器。
- 已添加标记禁用，添加成功后关闭选择器。
- 若进港或出港航班信息缺失，仅渲染存在航段；剩余空间不生成虚假占位数据。
- 若没有标记，`+` 位于标记行起始位置。

## 验证

- 单元测试覆盖类型相同/不同、字段回退、长航班号、空标记和标记溢出。
- 测试数据校验进出港计划时间、类型和标记字段完整性。
- 运行类型检查、完整测试与生产构建。
- 浏览器检查 260px × 140px 折叠态、动态展开态、最长航班号、最大标记数量和选择器层级。
