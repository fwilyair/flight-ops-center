# GSAP 动效优化设计

## 背景

当前页面以 React 状态驱动，已有 CSS transition、呼吸、脉冲、液态背景、抽屉和弹窗过渡。单元素反馈基本完整，但时间比例切换、搜索筛选、Tooltip 与引导线、详情浮层等多元素状态变化缺少统一编排，部分变化呈现为瞬移或彼此脱节。

本设计采用“混合编排”：保留 React 业务状态、原生滚动和简单 CSS 反馈，仅让 GSAP 负责需要时序或布局协调的变化。

## 目标

- 提升时间轴状态变化的可理解性，避免比例切换和筛选结果瞬移。
- 统一详情抽屉、弹窗、Tooltip 与引导线的进入退出节奏。
- 保持适中动效强度：功能反馈优先，增加有限层次感，不做演示型镜头效果。
- 支持 `prefers-reduced-motion`，允许动画被安全打断、覆盖和清理。
- 不破坏当前时间线固定在可视区域 30% 位置的既有逻辑。

## 非目标

- 不让 GSAP 接管物理滚动、滚轮判定、惯性或拖拽。
- 不修改时间与像素的换算规则、航班数据结构或业务状态模型。
- 不引入 ScrollTrigger 或 Draggable。
- 首轮不重做 Header 液态背景、全站 hover 和按钮微交互。
- 首轮不增加或调整持续性状态动画；现有 pulse 留到后续 P2 优化。

## 职责边界

### React

React 继续作为单一事实源，管理搜索、日期、时间比例、抽屉、弹窗、悬浮目标和航班状态。动画完成与否不得改变业务结果。

### CSS

CSS 继续处理颜色、边框、focus、hover，以及单元素 100–180ms 的简单反馈。现有无须编排的 transition 不迁移。

### GSAP

GSAP 处理以下场景：

- 两个以上元素需要按顺序或同时变化。
- React 更新导致元素位置或尺寸重排。
- 进入与退出需要明确清理和中断策略。
- Tooltip 与对应引导线必须作为一个整体出现或消失。

组件使用局部 timeline 和局部 ref。动画逻辑留在所属组件附近，不建立能控制全页任意元素的中央动画管理器。

## 代码组织

新增轻量 `motion/` 目录：

- `motion/tokens.ts`：快速反馈、布局变化、错峰间隔、打开/关闭时长和标准缓动。
- `motion/preferences.ts`：封装 `prefers-reduced-motion` 判断。
- `motion/gsap.ts`：集中注册所需 GSAP 能力并导出统一实例。

组件内通过 `useLayoutEffect` 和 `gsap.context()` 创建动画；组件卸载或依赖变化时调用 `revert()`/`kill()`。不额外抽象万能 `useAnimation` Hook。

## 动效设计

### P0：时间比例切换与布局重排

时间比例变化前记录时间轴内胶囊、绿色计划点、紫色计算点和关键基线节点的旧布局；React 完成新比例布局后，以 Flip 类布局过渡从旧位置动画到新位置。

- 动画仅改变视觉 transform，不改变最终 `left`、`top` 或时间计算结果。
- 当前时间红线不参与布局过渡，视觉位置保持在可视区域 30%。
- `scrollLeft` 仍由现有 `scrollToCurrentTime` 和用户手势判定逻辑维护。
- 布局变化时长 260–420ms，使用平稳减速缓动，不使用明显回弹。
- 连续切换比例时，新动画覆盖旧动画并从当前视觉状态继续。

### P0：搜索与筛选结果

搜索或日期筛选后，匹配航班行以轻微纵向位移和透明度错峰进入，错峰间隔 30–60ms。首个匹配行获得一次短暂强调，帮助用户建立搜索结果与时间轴位置的联系。

- 无结果状态立即显示，不增加加载假象。
- 列表动画不得延迟输入框响应或筛选计算。
- 快速连续输入时取消旧序列，只保留最新结果动画。

### P1：详情抽屉与弹窗

抽屉打开按遮罩、容器、标题/摘要、主体内容的顺序进入；相邻层级间隔 40–60ms。关闭顺序反向且总时长短于打开。

- 抽屉容器以水平位移和透明度为主，不使用大幅缩放。
- 弹窗以小幅 `scale`、`y` 和 `autoAlpha` 组合进入。
- 焦点设置、Escape 关闭和点击遮罩关闭不等待动画完成。
- 关闭期间再次打开时，从当前视觉状态反向播放或覆盖旧动画。

### P1：Tooltip 与垂直引导线

Tooltip、顶部时间标签和对应垂直引导线由同一 timeline 控制。

- Tooltip 使用小幅上移、缩放和透明度进入，时长 120–180ms。
- 引导线与 Tooltip 同时开始，避免两者先后闪烁。
- 快速跨越节点时直接覆盖旧目标动画，不排队播放。
- 绿色计划点与紫色计算点继续使用现有坐标结果，GSAP 不重新计算对齐位置。

## 动效参数

- 快速反馈：120–180ms。
- 布局变化：260–420ms。
- 列表错峰：30–60ms。
- 关闭动画：短于对应打开动画。
- 默认只动画 `transform`、`opacity`/`autoAlpha`；必须读取布局的 Flip 阶段集中执行，避免逐帧布局抖动。
- 不使用明显弹簧回弹；运行看板保持稳重、可预测。

## 状态流与清理

1. 用户操作触发既有 React 状态更新。
2. 需要布局过渡时，在更新前捕获旧布局。
3. React 提交最终 DOM 和最终业务状态。
4. 组件局部 GSAP timeline 从旧视觉状态过渡到最终状态。
5. 动画完成后清除临时 transform；组件卸载、依赖变化或新交互到来时立即清理旧动画。

动画层不写回航班业务数据，不以动画回调决定抽屉是否打开、筛选是否生效或比例是否已切换。

## 异常与降级

- ref 或目标元素不存在：跳过动画，保留 React 最终状态。
- 用户启用 `prefers-reduced-motion`：时长归零，直接呈现最终状态；滚动行为不额外改为平滑。
- 动画重复触发：使用覆盖策略终止旧 tween/timeline，避免队列积压。
- 组件卸载：清理 context、timeline 和临时 inline style，避免访问失效 DOM。
- GSAP 能力初始化失败：组件仍以无动画方式可用，不阻断搜索、滚动、抽屉或弹窗。

## 性能约束

- 时间轴动画优先使用 transform 与 opacity。
- 布局读取集中在状态切换边界，不在 `requestAnimationFrame` 中反复读取尺寸。
- 不为每个航班行建立常驻全局 timeline；只在交互发生时创建局部动画。
- 大量筛选结果使用短错峰并限制总时长，不让行数线性拉长等待时间。
- 页面隐藏或用户选择 reduced motion 时，不运行持续装饰动画。

## 验证方案

### 自动验证

- TypeScript 与 Vite 生产构建通过。
- 当前项目没有测试 runner，首轮不为动效单独引入测试框架；动效参数保持为纯数据，reduced-motion 与交互回归通过浏览器手工验证。

### 手工回归

- 5、10、30、60 分钟比例连续切换后，当前时间红线仍固定在可视区域 30%。
- 用户物理滚动仍能退出自动跟随；程序滚动不被误判为用户手势。
- 搜索、清空搜索、切换日期和无结果状态均立即正确。
- 胶囊、计划点、计算点和关键基线在过渡结束后与时间刻度准确对齐。
- 快速打开/关闭详情、弹窗和 Tooltip 时无闪烁、残留遮罩或失效点击层。
- 键盘焦点、Escape 和遮罩关闭行为不依赖动画完成。
- reduced-motion 环境下所有功能可用，状态变化无等待。

## 验收标准

1. 时间比例切换不再瞬移，且不改变时间轴最终坐标和滚动逻辑。
2. 搜索筛选结果具有短促、可中断的进入反馈，连续输入不积压动画。
3. 抽屉、弹窗、Tooltip 和引导线的进入退出节奏一致，快速反向操作无残留。
4. 当前时间线固定位置、用户滚动判定、胶囊与节点对齐全部通过既有回归场景。
5. `prefers-reduced-motion` 下直接呈现最终状态。
6. 生产构建通过，首轮改动仅覆盖 P0/P1 范围。
